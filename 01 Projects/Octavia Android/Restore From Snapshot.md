# Restore From Snapshot

> How to rebuild this repo if `C:\Projects\Octavia-Android` is gone. Written against the vault's `Code\` snapshot, which is the readable fallback rather than the primary copy.

## Try these in order

1. **The GitHub remote.** `gh repo clone N3cTr0/Octavia-Android` — private, and the primary off-machine copy. If this works, nothing below is needed.
2. **The vault snapshot**, below. It is the human-readable copy and the one that survives losing access to GitHub. It holds every source file we wrote; it is **not** a complete clone.

## What the snapshot does and does not hold

Held: every `.kt`, `.kts`, `.xml`, `.toml`, `.pro`, `.ps1`, plus `README.md`, `ROADMAP.md` and `versions.md`. That is all the source.

**Not held**, and each needs regenerating rather than restoring:

- `gradle\wrapper\gradle-wrapper.jar` — a binary. Regenerate with `gradle wrapper`, or copy from a freshly generated project (see below).
- The launcher icons under `res\mipmap-*` and `res\drawable` — `.webp` binaries from the template.
- `local.properties` — machine-specific, and git-ignored by design. Regenerated by the tooling, or written by hand with `sdk.dir`.
- `build\`, `.gradle\` — generated.

Because of the first two, the **fastest honest restore is a hybrid**: generate a fresh scaffold to get the binaries, then overwrite the source from the snapshot.

## The procedure

**1. Regenerate a scaffold** for the binaries and the wrapper:

```
android --no-metrics create --name "Octavia" --minSdk 28 -o C:\Projects\Octavia-Android empty-activity
```

**2. Restore every source file from `Code\`.** Each note carries `source-path:` in its frontmatter and holds exactly one fenced block. The content between the fences is the file, byte for byte with trailing whitespace trimmed — `tools\check-vault.ps1` verifies precisely this round trip on every run, so the guarantee is tested rather than hoped for.

Delete the template's placeholder sources first (`Navigation.kt`, `NavigationKeys.kt`, `ui\main\MainScreen*.kt`, `data\DataRepository.kt`) or they will collide with what you restore.

**3. Fix the package.** A fresh scaffold uses `com.example.octavia`; this repo is **`com.n3ctr0.octavia`**. The restored sources already say the latter, so only `app\build.gradle.kts` (`namespace`, `applicationId`) and the directory layout under `app\src\*\java\` need to match.

**4. Rebuild:**

```
$env:JAVA_HOME = 'C:\Users\N3cTr0\AppData\Local\Programs\Microsoft\jdk-17.0.10.7-hotspot'
.\gradlew.bat assembleDebug
```

**5. Re-init git** and push to a new private remote. See [[Build & Release]] for the toolchain, which is entirely user-scope and needs no elevation.

## The one thing that cannot be restored from here

Nothing in this repo holds a secret, so there is nothing to recover. Her **remote key** lives on the host in `data\remote.key` and is typed in on first run; her **per-run token** is in her log. Both are hers, not this app's — which is the point of [[Conventions & Security Model|the security model]].
